The Clacton by-election widget (`~/Downloads/clacton-vercel`) is deployed to Vercel under the **citizen-go-teammates** team scope, project `clacton-vercel`, live at https://clacton-vercel.vercel.app (deployed 2026-07-15). Data flows to the Supabase table `clacton_actions` (RLS-locked; service key set only as a Vercel env var by the user, never in chat). Env vars in Vercel: SUPABASE_URL, SUPABASE_SERVICE_KEY, CAPTURE_TOKEN.

**Why:** The user is non-technical; redeploys must be done for them via CLI.

**How to apply:** Node.js v24 + Vercel CLI live at `~/.local/node/bin` (not on default PATH — prefix commands with `export PATH="$HOME/.local/node/bin:$PATH"`). Redeploy with `vercel deploy --prod --yes --scope citizen-go-teammates` from the project folder. The page deals each visitor 1 of 16 subjects × 16 message wordings (user-approved copy; eight questions fixed verbatim; no residency/identity claims allowed in variants); combination sent as `variant` ("S3/M7"). Supabase columns `variant`, `stage`, `submission_id` all exist (verified 2026-07-16) with a unique index on submission_id; record.js upserts on it (two-stage capture: everyone saved at step 1 as stage='started', updated to 'completed' on send; the consent tick = GDPR consent to be contacted, it governs the email audience, not storage). record.js retains strip-and-retry fallbacks for missing columns. Everyone starts on variant S1/M1; shuffle deals alternatives. Candidate list is collapsed behind a summary line, ballot-paper (surname) order. Emails go To: questions@citizengo.net with candidates in BCC. Imprint footer "Promoted by CitizenGO UK, PO Box 81502, London W10 9FY." (compliance-approved 18 Jul). OG/Twitter share tags + /og-image.jpg (1200x600 candidate grid); og:url/og:image use the vercel URL — MUST update when a custom domain is set.

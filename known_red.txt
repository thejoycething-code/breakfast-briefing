# Fixture failures that are red ON PURPOSE, one substring of the failure message per line.
#
# Read by run_tests.py --known-red (hooks/pre-commit passes it). Matched on the MESSAGE, not
# the line number, because a line number moves as soon as anyone edits testcases.txt above it.
# A waiver that matches nothing FAILS the run: the case it covered is fixed, and an entry
# nobody deleted is standing permission for that failure to come back unnoticed.
#
# This file is not a way to make a red test go away. It is a way to keep the fixture honest
# while a failing-first correction waits for its fix - which is the normal state here, because
# testcases.txt is written red before the rule is edited. Every entry needs the date, who is
# waiting on it, and what has to be true before it can be deleted.
#
# EMPTY, and that is the correct state. The one entry it held - the cross-section repeat,
# open 08.09 to 10.09.2026 - was deleted on 10.09.2026 when ran_before stopped guarding on
# the section and the case went green. The stale-waiver check is what forced the deletion:
# it failed the run the moment the waiver stopped matching anything, which is the behaviour
# that stops this file rotting into standing permission.
